# Target Architecture — Fortune U Group Master AI Agent

## Topology

```
Internet
   │
   ▼
Reverse Proxy / HTTPS (Vercel for static site; nginx/Caddy for services)
   │
   ├─ fortuneugroup.in  ── static site (HTML) + lead forms
   │
   ▼
n8n (Community Edition)  ── workflow engine  (WF-01 … WF-15)
   │
   ├─ HTTP → FUG Master AI Agent  (automation/fug/orchestrator.py)
   │           └─ routes to specialist agents
   │
   ├─ NocoDB ──────────── CRM / data layer (fug_crm)
   ├─ WhatsApp Cloud API ─ templates, follow-ups
   ├─ Meta Graph API ──── Instagram / Facebook
   ├─ YouTube Data API ── video publish + metadata
   └─ Gemini API ──────── LLM for content + reasoning
```

## Separation of concerns

* **Frontend** — static site (this repo). No business logic, no secrets.
* **Automation** — n8n workflows + the Python Master Agent (`automation/fug`). Business logic lives
  here, credential-gated through env vars / n8n credentials.
* **Database** — NocoDB (production) with a local JSON fallback for development (`fug/storage.py`).

## Master Agent decision logic

For every incoming event the orchestrator (`fug/orchestrator.py`) runs:

1. Identify event type (`LEAD_CAPTURED`, `INBOUND_MESSAGE`, `FOLLOWUP_DUE`, …)
2. Identify / look up the lead in the CRM (dedup by phone/email)
3. Determine intent and select the specialist agent
4. Execute the workflow
5. Validate the result
6. Update CRM + automation logs
7. Decide next action (e.g. schedule follow-up)
8. Escalate to a human when required (`HUMAN_HANDOFF`)

## Approval-gated actions

The following require approval or an explicit flag — never executed blindly:

* Deleting data
* Bulk messaging
* Publishing content (YouTube / IG / FB)
* Changing website settings
* Any spend
* Modifying production infrastructure

`AUTO_PUBLISH=false` by default. Publish flows are blocked until a human approves.

## Observability

Every step writes to `AutomationLogs` (workflow_name, execution_id, timestamp, event_type,
lead_id, status, error_message, retry_count, duration, result). Failures go to `Errors` and are
handled by the Error Monitoring agent with bounded retry (no infinite loops).

## Security

* All credentials via environment variables / n8n credentials / OAuth — never in code or logs.
* `fug/secrets.py` redacts secrets from any output.
* Intake webhook supports an `X-Intake-Secret` header; request body is JSON-validated.
* Least-privilege API permissions and rate limits (esp. WhatsApp/Meta).

## n8n workflows (WF-01 … WF-15)

Importable JSON is generated by `automation/n8n/generate_workflows.py` into `automation/workflows/n8n/`.
Each workflow follows: **Trigger → Validation → Processing → Action → Logging → Error handling**.
